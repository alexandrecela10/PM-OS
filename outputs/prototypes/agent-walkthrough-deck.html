The pipeline

Seven steps, each with a visible input and output

1 · INGEST

Parse and index every document with provenance

2 · DETECT

Compare field reality against the contractual baseline

3 · MAP CONTRACT

Find the governing clause, including amendments

4 · COMPUTE DEADLINES

Deterministic date math, never LLM-generated

5 · BUILD EVIDENCE

Chain every claim to a cited source line

6 · DRAFT + IMPACT

Notice draft, schedule and cost impact via peer agents

7 · HUMAN GATE

Named approver; nothing leaves without sign-off

Steps 2, 3, 5 and 6 use the LLM to read and reason. Step 4 is plain code — a date calculation from extracted anchors, checkable by hand. The split is deliberate: judgment where language is the problem, determinism where being wrong is unrecoverable.

Step 3 — Map to the contract

Which clause governs, and what did the amendments change?

Input 
GC 4.12(b): "Formal notice with particulars
shall be given no later than 28 days after
the Contractor became aware…"
Amendment 2 (14 Mar 2026): "28 days"
replaced with "21 days" for events in
Areas 6-8 after Area 7 access handover.
01-contract-extract-gc-4.12.md
→
Throughput
  • Retrieve clauses matching event type: GC 4.10, 4.12, 20.1
  • Apply amendments in date order — the base clause alone is wrong
  • Extract obligations for both sides: contractor's bar and the Owner's GC 20.1 notice duty
→
Output 
governing: GC 4.12(b) as amended (Amd 2)
contractor_bar_days: 21  (not 28)
owner_notice: GC 20.1, 28 days
anchors: awareness = DR-1042 (04 Aug 2026)
The amendment catch is the demo moment. A team working from the base contract assumes 28 days. The agent reads Amendment 2 and knows the real bar in Area 7 is 21.

Step 4 — Compute deadlines

Deterministic date math. The LLM never touches this.

Input

Structured anchors from step 3:

awareness_date = 2026-08-04  (DR-1042)
contractor_bar = 21 days    (GC 4.12(b) amended)
owner_notice   = 28 days    (GC 20.1)
today          = 2026-08-26
→
Throughput 
contractor_deadline
  = 2026-08-04 + 21d = 2026-08-25
owner_deadline
  = 2026-08-04 + 28d = 2026-09-01
days_remaining(owner)
  = 2026-09-01 − 2026-08-26 = 6

Plain code. Auditable, testable, reproducible.

→
Output 
contractor bar: EXPIRED 25 Aug 2026
owner GC 20.1 deadline: 01 Sep 2026
status: 6 days remaining → ALERT

This is the "6 days" banner in the live demo.

Design rule: anything where an error is unrecoverable (dates, sums, deadline math) is computed by code from extracted anchors, with the anchors themselves human-checkable via citations.
